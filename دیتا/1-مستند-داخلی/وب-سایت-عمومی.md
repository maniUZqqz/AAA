# وب‌سایت عمومی آپ‌مارکت

برنامه‌ی سایت عمومی (بازاریابی و فروش) — جدا از پنل محصول که در
`Code/UpMarket/frontend` ساخته شده.

> مبنا: یادداشت خام مالک پروژه، سازمان‌دهی‌شده. متن اصلی در `../0-آرشیو/`.

---

## چرا فقط Landing Page کافی نیست

سایت باید همزمان چند کار انجام دهد: فروش SaaS، ایجاد اعتماد، توضیح قابلیت‌ها،
شفافیت قیمت، نمایش نمونه خروجی، تبدیل بازدیدکننده به ثبت‌نام، و در بلندمدت
تولید ترافیک ارگانیک. یک صفحه نمی‌تواند هر شش کار را خوب انجام دهد.

---

## ساختار صفحات

| صفحه | هدف | نکته |
|---|---|---|
| **Home** | تبدیل بازدیدکننده به ثبت‌نام | بالای صفحه باید نمونه‌ی خروجی واقعی باشد، نه توضیح |
| **Features** | توضیح قابلیت‌ها | نه چند کارت تبلیغاتی — جریان واقعی کار |
| **How It Works** | نمایش فرایند واقعی محصول | همان ۶ مرحله‌ی اسلاید ۴ ارائه |
| **Pricing** | پلن‌ها، محدودیت‌ها، مقایسه، CTA | اعداد باید با `data.json` یکی باشند |
| **Showcase** | نمونه‌کارهای واقعی | از `../3-نمونه-کار/` تغذیه شود |
| **About Us** | داستان، مأموریت، تیم | ساخت اعتماد |
| **Blog** | مقالات بازاریابی، فروش، AI | موتور SEO |
| **Contact** | ارتباط با تیم | |
| **FAQ** | قیمت، خروجی، امنیت، نحوه استفاده | |
| **Login / Sign Up** | ورود به پنل محصول | |

> **تصمیم باز:** اینکه Features یک صفحه باشد یا چند صفحه‌ی جدا
> (AI Content، Product Analysis، Competitor Analysis) به استراتژی SEO
> بستگی دارد و بعداً تصمیم گرفته می‌شود.

## الزامات فنی

| مورد | تصمیم |
|---|---|
| فریم‌ورک | Next.js + React (برای SSR و SEO) |
| بک‌اند | Django REST Framework — همان بک‌اند پنل |
| SEO | اولویت بالا — SSR، متادیتا، سایت‌مپ، داده‌ی ساخت‌یافته |
| ریسپانسیو | الزامی |
| زبان | دو زبانه (فارسی / انگلیسی) |
| تم | دو تم (روشن / تیره) |

> پنل محصول (React + Vite) جداست و همان‌طور می‌ماند؛ سایت عمومی به‌خاطر SEO
> به رندر سمت سرور نیاز دارد.

## ایده‌های محصولی که باید در سایت دیده شوند

این‌ها از یادداشت خام آمده‌اند و هنوز به نقشه راه اضافه نشده‌اند:

- **کیفیت عکس محصول** — مشتری باید *خودِ محصولش* را ببیند، نه یک تصویر ساختگی.
  (در کد پیاده شده: پوستر با `flux_img_edit` از عکس واقعی محصول ساخته می‌شود.)
- **تشخیص موقعیت‌های حساس در پشتیبانی** — وقتی ایجنت احساس خطر کرد یا کاری
  از دستش برنیامد، به پنل مالک فروشگاه اطلاع بدهد.
  (در کد پیاده شده: `Notification` + وضعیت `ESCALATED` + تیکت پشتیبانی.)
- **تحلیل داده‌ی محصول و رقبا از وب** با API.
  (در کد پیاده شده: ریسرچ دیجی‌کالا / ترب / جستجوی وب.)
